# 内容摄取（自己的内容源）

Traver 自己不带数据。而最详细的旅行信息往往不在任何 API 里：它在一篇小红书笔记、一条抖音评论、一份大众点评评价、一篇携程攻略里。这些平台**都没有公开 API**，抓取它们既违反服务条款，也意味着要持有使用者的登录态。

所以这里走的不是「数据源」，而是**摄取**：使用者把自己已经能看到的内容交给 Traver，Traver 从中提取结构化事实——而每一条事实都保持标注为「某个人说的」。

## 为什么用规则而不是模型

提取器（`services/ingestion.py`）是纯规则式的，这是设计决定而非能力不足：

- **零配置也能用**。没有接任何模型的使用者照样能拿到笔记里的价格、闭馆日与提醒，与全系统的「渐进增强」一致。若这里依赖模型，摄取这条路就只对已经配好模型的人存在。
- **每条规则说明自己的依据**。`ExtractedFact.reason` 写出「「元」紧跟数字」这类理由，所以一个读错的判断是可诊断的，而不是玄学。
- **它不会凭空补全**。让语言模型「提取事实」，它会产出笔记里根本没有的、看起来很合理的人均消费；这里在文本没说的地方就是不说，这才是规划工具需要的行为。

一个方向的偏向是刻意的：**宁可漏掉一条，也不编造一条**。漏掉一条提示让旅行者损失很小，编造一个价格让他们损失金钱。

## 五条诚实规则

| 规则 | 落地方式 |
| --- | --- |
| **声称不是测量** | 提取结果一律是 `ContentReference` / `source_type=user_provided`，永远不是 `commercial_fact`。它可以作为估算进入预算，绝不能覆盖报价 |
| **每条事实引用原文** | `evidence` 是输入中**逐字**的那一段，`char_start/char_end` 指向它。引用不出自己的事实不会被输出 |
| **置信度描述的是「读得准不准」** | 只说我们有多确定文本是这个意思，从不说我们有多确定这是真的。两者是不同的数字，混淆就把观点洗成了事实。前端文案同样受限（`识别明确` / `识别一般` / `仅为线索`，`apps/web/lib/ingestions.ts`） |
| **缺失就保持缺失** | 文本没提价格就没有价格，不是 0。一个过度积极的提取器最典型的失效就是补上读者期待的那个数字 |
| **发布时间通常缺席，而缺席要被说出来** | 页面写了日期就带上；没写就如实记为「发布时间未知」，而不是默认为「刚刚」。一条 2019 年的建议与昨天写的，在粘贴框里看起来完全一样 |

## 提取什么

| 类型 | 例子 | 说明 |
| --- | --- | --- |
| `price` | 人均 80-120 元 / 门票 ¥75 | 只在**货币标记**旁边才认。光秃秃的数字是日期、公交线路或楼层数——把它当价格是提取器凭空造预算的经典方式。区间保持为区间，不做平均 |
| `duration` | 建议游玩 2 小时 / 排队 40 分钟 | 单位由**匹配到的规则**给出，绝不从捕获组数量推断 |
| `opening_hours` | 周一闭馆 / 营业时间 09:00-17:00 | 需要「周X」与「闭馆/休息」类词**同现**。「周一」是日期，「休息」是打盹 |
| `warning` | 排队很久、宰客、避坑 | 需要具体的负面信号词。泛泛的「不太好玩」是情绪，把它升级成警告等于给一个陌生人的心情以证据的分量 |
| `tip` | 建议早点去 | 建议口吻 |
| `place_mention` | 推荐去灵隐寺 | 靠**后缀**（寺/塔/馆/湖/山/古镇/步行街…）识别。中文没有大小写也没有词边界，没有后缀约束就只是在猜任意子串 |

### 两个被测试钉住的提取陷阱

- **地名修剪**。「我昨天去了杭州西湖」最初会整句变成地名。现在按「不可能出现在地名里」的字符切分并取最后一段，得到「杭州西湖」。`和 / 与 / 及` 被**刻意排除**在这个集合之外——它们既是连词，也是真地名的首字（和平公园），当作噪声会把要清理的名字弄坏。
- **「周一闭馆」不是地名**。它以「馆」结尾，于是后缀规则把它报成了一个叫「周一闭馆」的景点——一句关于**关闭**的话变成了目的地。现在「表示这里关门的词不可能同时是它的名字」被写成规则。

## 书签小工具

`GET /api/v1/content/bookmarklet` 生成脚本。它在**使用者自己已登录的浏览器**里、在他们正在看的页面上运行，只读取标题、正文文本、作者、发布时间与网址。

- 它**不**读 cookie、localStorage、sessionStorage 或任何 token；有测试断言这些字符串不出现在脚本里（`test_the_bookmarklet_never_carries_or_asks_for_a_password`）。读它们会把一个便利功能变成凭据收集工具。
- Traver **从不**向这些域名发起请求，也不保存任何登录态。
- 脚本由服务端生成而不是写死在前端：前端再复制一份就会与它要请求的端点漂移，而失效表现是「书签某个时候开始不工作了」。
- 路径是 `/content/bookmarklet` 而不是 `/ingestions/bookmarklet`：后者有个 `/ingestions/{ingestion_id}` 兄弟路由，靠注册顺序才能正确解析——一个会因为有人重排文件而坏掉的路由。换个前缀就消除了这个隐患。

## 如何进入行程

摄取内容进入 `TripPreview.ingested_notes`，**贴着它所谈论的那个地点**：

- 匹配规则是把事实的**证据句**与已聚合实体的名称对照，其次才是提取出的地名。只用提取的地名匹配时，「住成都天际酒店」永远关联不上那家酒店——名字一直在句子里，只是「酒店」不是提取器认识的地名后缀。
- **只匹配，绝不合并**。实体的自有字段一个都不改。笔记里的价格与时长是别人的记忆和偏好；让它们写进实体，就是又一次把观点洗成事实。有测试逐字段比对前后实体（`test_a_note_never_overwrites_a_measured_entity_field`）。
- **匹配不上的提及照样报出来**。那是我们数据里的缺口，藏起来会让笔记看起来被完整利用了。它以 `matched: false` 列出，说明该地点还没有坐标、因此进不了路线。
- **每条都进入引用**（`source_references`）。没有引用来源的内容，其出处无法核对。
- **排序把注意事项放前面**：闭馆日会改变能规划什么，提示不会。同样排序会把唯一能省下一个上午的事实埋掉。

### 时效性

`user_content` **刻意不在** `MAX_AGE_SECONDS` 里。一篇写得好的街区指南不会像预报那样按时间表失效——关键是**公开它的年龄**，而不是对它设阈值。给它一个上限只会让每一篇真正有用的旧攻略都触发警告，而读者就是这样学会忽略警告的。

没有标注发布时间的笔记照常走 `SOURCE_SILENT` 路径，被报为「数据时间未知」，不会被当作最新内容。

## 数据模型

`content_ingestions` 表（迁移 `a1f7c93e5b20`）：

- `content_text` 逐字保存输入。提取结果只能对着它核对，而没人能核对的提取是断言而不是引用。
- `published_at` **可空，而这个 null 就是重点**：它记录「页面没有说」。默认成摄取时间会让每篇旧笔记看起来都是新的。
- `facts_json` 用 JSON 而不是子表：一篇笔记的事实总是整块读取，从不单独查询，也从不参与 join。
- 每一行都按 `owner_id` 过滤。保存的笔记会暴露作者在哪吃、何时出行，因此 `None`（未启用认证的单用户模式）与 `""`（真实的匿名属主）必须保持区分——把两者合并会让一个匿名使用者读到另一个的笔记。跨属主读取返回 **404 而不是 403**：确认某个 id 在别的属主下存在，本身就是在泄露它存在。

## API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/api/v1/ingestions` | 提取并保存。返回提取结果而不只是 id——真正的问题永远是「你从中读到了什么」 |
| `GET` | `/api/v1/ingestions` | 自己的笔记，最新在前 |
| `GET` | `/api/v1/ingestions/{id}` | 单条 |
| `DELETE` | `/api/v1/ingestions/{id}` | 删除 |
| `GET` | `/api/v1/content/bookmarklet` | 书签脚本 |

计划在每次生成时**重新读取**笔记，因此刚保存的立刻生效、删掉的立刻消失。读取失败被吞成空列表：使用者自己的可选笔记，绝不能弄坏行程规划。

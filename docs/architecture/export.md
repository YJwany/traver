# 导出：让文档自己交代自己

导出是唯一一个**离开应用**的产物。应用内的每个数字旁边都有来源标签、时效性面板和能力矩阵；导出的文件没有。
它会被放进下载文件夹、打印出来、导入日历，几个月后才被打开——那时它的数字看起来和刚写下时一样权威，
而没有任何东西能回答"这个还成立吗"。

所以导出不是时效性规则的例外，而是它最强的用例。

## 两个格式，两种职责

| 格式 | 端点 | 职责 |
| --- | --- | --- |
| Markdown | `GET /trips/{id}/export.md` | 完整记录：行程、已知限制、预算、以及**每条来源的两个时间** |
| iCalendar | `GET /trips/{id}/export.ics` | 手机上真正会用到的那部分：逐项事件，每个事件自带一条简短的交代 |

iCalendar 刻意**不**做完整记录。把 Markdown 的内容塞进 `DESCRIPTION` 会被所有客户端折叠成一行"…"。

## 三条写进文档的规则

### 1. 文档写明自己的生成时间，并说明它不会更新

> 由 Traver 于 **2026-09-28 12:00 UTC** 生成……
> 本文档是导出那一刻的快照，**其中的数字不会自动更新**。

行程是快照，文件是更永久的快照，而 Markdown 和 iCalendar 都不会自己说明这一点。

### 2. 每个事实带**两个**时间，以及第二个时间的含义

`fetched_at` 回答"我们何时去问"，永远已知（模型里是必填）。`observed_at` 加上 `observed_at_basis` 回答
"这个答案有多旧"——而多数免费来源的答案是"不知道"，这一点被写出来而不是省略。

来源表的最后一列写着 `observed_at 的含义`（`来源自报数据时间` / `本次请求实时计算` / `来源未提供数据时间`）。
没有这一列，`SOURCE_SILENT` 来源的 `observed_at` 就是我们的抓取时间，年龄会读起来像数据年龄。

**相对时间永远标注它相对于什么。** "3 分钟前"写进文件就是一句等着变成假话的话。绝对时间同时打印，
相对时间标明"导出时计算"。

### 3. 「无法确认」与「已过期」分开，而且不靠辅助字段下结论

Markdown 的两个小节：`已超出可接受范围` 与 `无法确认数据年龄`。合并它们就是双向的谎——
把沉默报成过期是没依据的断言，而只打印过期清单会留下一个"没有警告"的空白，读作"都查过了"。

关键在于**结论从哪里来**。最容易写成的版本是：

```python
if not stale_facts and not age_unknown_facts:
    print("全部来源都给出了数据自身时间")  # 错
```

`age_unknown_facts` 为空**不等于**核实过。旧快照里这个字段可能根本不存在，而"不存在"与"空列表"
在 JSON 上无法区分——于是文档会凭空造出一个从未发生过的核实。这正是 Web 端
`freshness-coverage.tsx` 已经修过一次的缺陷（那里是缺字段时按未知处理，绝不渲染「全部可验证」）。

导出的修法是**换一个来源下结论**：`FreshnessService.age_is_known()` 是 `observed_at_basis` 的纯函数，
而 `observed_at_basis` 就印在文档自己的来源表里。所以"每条来源的年龄都可核实"是从**文档已打印的内容**
推出来的，不可能因为某个字段缺失而被制造出来。审计产出的 `age_unknown_facts` 仍然优先使用（它已经
应用了按事实类型的时限策略，而"没有时限就不判定"是刻意的），缺失时回退到按 basis 归并。

`tests/unit/test_export_documents.py` 用"引用全是沉默来源 + `age_unknown_facts` 为 `[]`"这个状态
钉住它：文档必须说"无法判断"，不得说"全部标明"。

## iCalendar 的三个结构性陷阱

写日历时没有异常、没有报错，客户端只是"少了一个事件"。所以这几条是结构性的，必须测。

### 折行以**字节**计，但绝不能在字符中间切

RFC 5545 规定内容行不超过 75 字节，续行以空格开头。中文每字 3 字节，所以折行会持续落在字符中间。

第一版实现切的是编码后的字节，再对每段用 `errors="ignore"` 解码，理由是"下一段会补上剩下的字节"。
这个理由是错的，而且**静默毁掉文本**：

```
期望  间，无法判断数据新旧。数据来源未提供时间
实得  间，无法判断数据新旧。数来源未提供时间
```

`据` 和 `新` 跨在边界上，两半都被丢掉。日历仍然能解析、事件仍然出现，只是少了两个字。
现在折行在字符串上走：逐字符累积，直到下一个字符放不下为止，因此永远不会落在多字节序列中间。
测试在多种长度上要求折行—还原**完全等值**。

### 时间是**浮动时间**，不是 UTC

行程时间来自 `datetime.combine(day_date, time(9, 30))`——**naive**，含义是"目的地当地 09:30"。
规划器不知道目的地时区，而猜一个会让每个事件平移几小时却依然看起来合理。

所以事件写成浮动时间（`DTSTART:20261003T093000`，无 `Z`、无 `TZID`），这是 RFC 5545 表达
"这个墙上时钟时间，时区未指定"的方式——恰好就是已知的东西。加 `Z` 是断言 UTC；加 `TZID` 是断言
一个行程里没有任何东西确立过的时区；两者都会把一个未知变成看起来确定的数字。

代价是真实的，并被写出来：客户端会按**本机时区**渲染浮动时间，所以一份 东京 的行程导入到设为
伦敦 的设备上会显示 09:30 伦敦时间。已知目的地时区时（天气来源会带回 `Asia/Shanghai` 这类值）
会把它写进日历描述供读者解读，但**文件从不静默换算**。`zoneinfo` 需要 tz 数据库，而项目没有声明
`tzdata` 依赖，于是同一份行程在不同机器上会导出成不同的时刻——一个含义取决于哪台机器生成它的文件，
比一个说清自己不知道什么的文件更糟。

### 免责声明写在**每个事件**上，不只在日历上

事件会被单独转发、单独导入。日历级的说明不跟着走。所以每个 `VEVENT` 的 `DESCRIPTION` 里都带
生成时间、快照说明、时间基准，以及数据覆盖的一段话。

`STATUS:TENTATIVE` 同理：行程是计划，不是预订。写成 `CONFIRMED` 和把估算时长当实测时长是同一类断言。

## 下载文件名：一个真实 500

```python
safe = "".join(c if c.isalnum() else "-" for c in trip.profile.destination)
```

这行看起来没问题，实际上**让每个中文目的地都返回 500**。HTTP 头部的值是 latin-1，
`Response(headers={...})` 会把值按 latin-1 编码，而 `"杭".isalnum()` 是 `True`——所以中文原样通过，
然后抛 `UnicodeEncodeError`。也就是说，恰好是这个项目最主要的用户场景挂了。

纯函数测试全都通过，因为缺陷住在它们和客户端之间的传输层。所以
`tests/integration/test_export_over_http.py` 用真实 HTTP 请求走一遍。

修法按 RFC 6266 同时发两个名字：

```
Content-Disposition: attachment; filename="trip-2026-10-03.md"; filename*=UTF-8''%E6%9D%AD%E5%B7%9E-2026-10-03.md
```

ASCII 回退给老客户端，`filename*` 给所有现代浏览器（它们优先用后者）。`filename*` 的值整段百分号编码
（`safe=""`），这同时让头部注入不可能：目的地里的引号或换行会变成 `%22` / `%0A`，而不是终止头部。

导出是快照，所以响应带 `Cache-Control: no-store`——重新导出很便宜，发一个陈旧文件正是这一整个
领域要防的事。

## 前端的名字解析

`apps/web/lib/export.ts` 里的 `parseContentDisposition` 优先 `filename*`，回退到 `filename`，
都没有就用调用方给的名字。读错的那一个不会报错——下载仍然成功，只是得到 `trip-2026-10-03.md`
而行程是杭州的。这种"不出声地差一点"正是要单独测的那类东西。

不能用 `<a href>` 直接下载：API 用 bearer key 认证，而锚点请求不带 `Authorization` 头，
所以恰好是配好密钥的用户会拿到 401。文件用同一个 API 客户端取回再作为 blob 交给浏览器。

## 测试与探针

- `tests/unit/test_export_documents.py` — 两个文档的内容与结构、折行等值、浮动时间、
  每个事件的免责声明、UID 稳定、预算标记取自 `is_estimate`、文件名编码
- `tests/integration/test_export_over_http.py` — 真实 HTTP：中文目的地不 500、下载头、
  快照声明、未知行程 404、别人的行程 404 且响应体不含内容
- `apps/web/lib/export.test.ts` — 文件名解析的六种输入
- `apps/web/app/components/export-panel.test.tsx` — 面板文案、下载调用与失败可见性
- `scripts/probe_export_documents.py` — 真实规划一份行程并导出，打印两个文件供阅读，
  同时断言那些"只有读的人才会发现"的性质（行高、CRLF、浮动时间、每条事件都带声明）

# 展示层：示意图、坐标与「不要画得像地图」

## 位置示意图是什么

行程页上有一个面板，把这次计划里的酒店、餐厅、景点按坐标摆在一个方框里。它回答的问题只有一个：**这些地方彼此离得近不近**——上午的景点和晚上的餐厅是不是在城市两头。排路线时这是最先要看的，而纯文字列表看不出来。

它**不是地图**：没有底图、没有瓦片服务、没有投影，屏幕上的距离和方位都不成比例。这一点必须写在界面上，否则一个方框里的点会被当成地理事实来读。面板标题因此写「示意图（非按比例）」，而不是「坐标视图」——旧标题暗示了它是个视图，而这个暗示是错的。

同样的区分在服务端已经立过：`PlaceResolution` 携带的是**直线距离**并明确标注为直线，从不据此推导通行时间。面板不画任何看起来像海岸线或道路的东西，是同一个原则在界面上的延续。

## 那个写死的成都

面板的方框原本是这么算的：

```tsx
const minLat = Math.min(...lats, 30.6), maxLat = Math.max(...lats, 30.6);
const minLon = Math.min(...lons, 104.0), maxLon = Math.max(...lons, 104.0);
```

`30.6, 104.0` 是成都。于是方框从来不是「这次行程的包围盒」，而是**这次行程与一个固定城市的并集**。

没有测试覆盖过这个面板（`apps/web` 下当时没有任何地图相关的测试），所以这里直接量出来。三次真实行程，各自的三个点，旧算式与现算式的落点：

| 行程 | 旧：x 跨度 / y 跨度 | 现：x 跨度 / y 跨度 |
| --- | --- | --- |
| 成都 | 23.9% / 26.5% | 76% / 76% |
| 杭州 | **0.1% / 3.8%** | 76% / 76% |
| 丽江 | **0.2% / 0.1%** | 76% / 76% |

杭州三个点旧落点是 `(87.9, 79.9)`、`(87.9, 78.2)`、`(88.0, 82.0)`——**全部挤在右下角 0.1% 宽的一条竖线里**，面板其余部分完全空白。丽江更极端：三个点落在同一个位置（y 跨度 0.1%），看上去像只有一个地点。

成都的旧跨度是 23.9% / 26.5%，虽然仍不是它自己的包围盒（被固定城市撑开了），但至少能看——**这大概就是它活下来的原因：所有 fixture 和所有手动检查都用成都。**

部署服务的目的地越多，画错的行程就越多；而越是一个人自己试，越容易试的都是同一个城市。

**与「成都市中心」写死在评分器里、`city == destination` 的相等比较、`(0.0, 0.0)` 当作原点、「快照通常只有几分钟」属于同一类：一个常量其实是某一个地点的属性。**

## 规则搬到 lib/map.ts

界面里的算式没法测，所以规则搬到了 `apps/web/lib/map.ts`，配 `lib/map.test.ts`（12 条）。两个函数：

- `boundsOf(points)` —— 方框只由给进来的点决定；**没有可画的点就返回 `null`，而不是一个默认方框**。默认方框是在断言行程在哪里，成都就是那个断言。
- `placePins(points)` —— 返回与输入**等长**的数组，坐标不可用的位置是 `null`。丢掉它们会重新编号图钉，把标签安到错误的点上。

四个判断值得记下来：

- **`(0.0, 0.0)` 不是地点。** 它是未设置坐标序列化出来的值，也是大西洋上一个真实的点。留在里面会把方框拖到几内亚湾，其余每个点都挤进一个角落。纬度超出 ±90、经度超出 ±180 同样拒绝。
- **单个点（或若干重合的点）居中，不拉伸。** 零跨度放大出来只是噪声，而把一次行程里唯一的地点放在角落，等于暗示它与面板边缘存在某种关系——那种关系不存在。
- **返回 `null` 而不是 `0`。** 和 `ScoreBreakdown` 里缺失的维度一样：`0` 是一个测量值，`null` 才是「没测到」。
- **没有可画的点就渲染空状态。** 空面板说的是「这次计划里没有可用的坐标」；一个默认方框说的是「它们在这里」，而后者是编的。

## 防护

五个变异全部被抓，其中「把成都写回方框」触发 6 条测试失败：

| 变异 | 结果 |
| --- | --- |
| 包围盒重新用成都打底 | 6 条失败 |
| 接受 `(0.0, 0.0)` 为地点 | 1 条失败 |
| 零跨度被拉伸而非居中 | 2 条失败 |
| 北画在下方 | 1 条失败 |
| 丢弃不可画的点（图钉错位） | 1 条失败 |

变异脚本本身也是先写错过一次：它在每轮开始前不还原文件，于是第 N 轮的「基线」跑的是第 N-1 轮的变异结果，把六个**已经**被抓住的变异报成了「未抓住」。**护栏和一个坏掉的变异脚本长得一模一样**，所以脚本每轮必须先还原再跑基线。

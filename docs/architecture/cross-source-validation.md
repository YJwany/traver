# 多源交叉验证 / cross-source validation

这份文档记录一个具体的诚实性缺陷，以及修掉它之后系统承诺什么、不承诺什么。

## 问题：合并本身就是一次无声的表态

Traver 把多个来源的同一家酒店、餐厅、景点合并成一条记录。原来的合并只处理了一种情况 —— **某个来源没说话**：如果 OSM 给了门票价而高德没给，就采用 OSM 的。这是对的。

但真到了**两个来源都说了、而且说的不一样**的时候，原来的代码：

1. 留下最先遍历到的那条值；
2. 仍然把**两个**来源的引用都挂在这条记录上。

于是页面上出现的是「¥60」，旁边列着两个来源。读者看到的是**两个来源互相印证**，而实际上其中一个来源说的是 ¥80。这不是显示错误，是把分歧伪装成了共识 —— 比报错更糟，因为报错会被人发现。

这个缺陷能长期存在，是因为原来的合并只做加法：只往记录上追加引用，从不比较值。没有任何测试能看见它。

## 现在承诺什么

每条可比字段上都有一本**完整的账**（`FieldDisagreement`）：每个来源说了什么、什么时间说的，以及系统留下了哪一个、为什么。

| 承诺 | 含义 |
| --- | --- |
| 全部原始说法都保留 | `claims` 里列出每一个来源的值，不只列落选的那些 |
| 留下的值可追溯 | `chosen_source` + `chosen_value_text` 指明页面上那个数字是谁说的 |
| 选择规则写出来 | `chosen_reason` 说明依据，不是让读者猜 |
| 分歧不被抹平 | 不做平均、不取中位数、不「综合判断」出一个谁都没说过的值 |
| 顺序不影响结论 | 来源注册顺序不是事实判断的隐藏输入 |

## 现在**不**承诺什么

- **没有分歧 ≠ 数据被核实过。** `disagreements == []` 只意味着**说过话的来源彼此一致**。三个来源都没提门票价，和三个来源都说是 ¥60，是两件不同的事，面板上的文案必须说清这一点。
- **不是事实核查。** 系统比较的是来源之间的一致性，不是与现实的真实性。两个来源可能一起错。
- **不判断谁「对」。** 留下的是「按规则更该采信的一条」，不是「正确的一条」。旧的来源可能是对的，新的来源可能是错的。

## 选择规则

按顺序，第一条能分出胜负的就用它：

1. **来源实际报告的值 > 系统推算的估算值。** 估算不是证据,所以不参与「谁更新」的比较 —— 拿一个我们自己推出来的数和一个来源亲眼看到的数比时间先后，是在比两种不可比的东西。
2. **观测时间最新的。** 时效性是 Traver 的硬约束，这条事实的观测时间更近就更该采信。
3. **抓取时间最新的。** 用来在观测时间相同时打破平局。
4. **来源名。** 纯粹为了确定性 —— 让结果不依赖注册顺序。

数值相等的不同写法（`60` 与 `60.00`）不算分歧；营业时间只要窗口一致就不算分歧，与列出的顺序无关；币种不同算**不同的事实**（`¥60` 和 `US$ 60` 是分歧，不是相同）。

## 没有时间戳的情况

如果一条说法**没有任何来源引用**，它拿不到观测时间。这时：

- 记为 `_NO_TIME`（`datetime.min`），**而不是 `datetime.now()`**。把缺失的时间默认成「现在」，会让最无法归因的值看起来最新 —— 正好是时效性工作要防的那种倒置。
- 它因此永远赢不了有真实时间戳的说法。
- 若两边都没有时间戳，`chosen_reason` 明说这是按稳定顺序取的、不代表更可信，而不会假称做过时效判断。

## 一处刻意的边界

`_collect_claims` 在**任何成员被修改之前**读取所有说法，并且**跳过已经带有分歧记录的字段**。

这个顺序是有承重的：

- 先合并引用再读说法，主记录的标量值就会配上别人的引用，于是那个值既被**错误归因**给另一个来源，又**继承了那个来源的时间戳** —— 结果是一个错误的数字戴着自信的标签，比没有数字更糟。
- 已合并过的记录，它的标量值已经不再对应任何一个单独的引用（留下的是赢家的值，而 `source_references` 列着所有来源）。再从它上面读说法，就会把留下的 ¥80 记到明明说的是 ¥60 的来源名下。

所以这三个函数的契约是：**输入必须是刚刚抓取的、单一来源的实体**。跳过那一步是为了让这个契约在代码里成立，而不只是写在注释里。回归测试：`test_a_nested_merge_does_not_misattribute_the_merged_value`。

## 存下来、传到页面上

分歧存在行程聚合里，随 `state_json` 一起持久化，无需迁移。两处断点都必须有人守：

- **写入丢失**：如果持久化哪天改成逐字段投影，新字段会被静默丢掉，API 就会返回一条「没有分歧」的记录 —— 一个数字配着好几个来源名，正是这个字段要防的那种伪造共识。
- **API 不可达**：机制再正确，只要不出现在页面真正拉取的那个响应里，对任何人都没有效果。

所以除了单元测试，还有 `tests/integration/test_disagreement_persistence.py`，包括一条**通过 HTTP 读回**的用例，以及 `disagreements == []` 必须存在且为空、以便区分「一致」与「字段被丢了」。

## 页面

`apps/web/app/components/disagreements.tsx` 渲染这些记录。三条要求：

1. **列出全部说法**，不只列落选的。「两个来源，¥60 和 ¥80」与「三个来源，两个说 ¥60」是不同的情况，只有完整列表能让人分辨。
2. **点名当前显示的是哪一条**，因为卡片上那个数字才是旅行者会照着行动的。
3. **空面板不能读成「已核实」**。没有分歧时该组件不渲染任何东西（一个永远出现的面板会被训练成被忽略），出现时必须写明「没有这一栏不代表数据已被核实」。

## 为什么值得做

用户的原始要求是「不要吹嘘你懂吧」。把某一个来源的价格和另一个来源的引用并排显示，就是**结构性的吹嘘**：不需要任何一句夸大其词，界面自己就制造了不存在的共识。修掉它不需要新数据源，只需要在合并时把已经知道的事情如实说出来。

## 验证

```bash
python -m pytest tests/unit/test_cross_source_validation.py -q
python -m pytest tests/integration/test_disagreement_persistence.py -q
cd apps/web && npx vitest run app/components/disagreements.test.tsx
```

- `tests/unit/test_cross_source_validation.py` —— 一致时沉默、分歧时全量记录、选择规则的两个方向、第三个来源能把结论扳回去、币种/估算/营业时间这些边界、`specs_for` 对未声明的实体类型报错。
- `tests/integration/test_disagreement_persistence.py` —— 存库往返、空列表的语义、**HTTP 响应可达**、嵌套合并不误归因。
- `apps/web/app/components/disagreements.test.tsx` —— 面板渲染全部说法、点名留下的值、说明规则、字段名回退；空与缺失都渲染为空。

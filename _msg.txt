feat(web): API key entry, typed API client and web tests

The Web app was still calling `fetch` directly, so enabling `AUTH_ENABLED=true`
on the API broke every page with a bare 401 and no way to fix it from the UI.

Web authentication:

* `lib/auth.ts` stores the key in `localStorage` and deliberately does NOT read
  `NEXT_PUBLIC_API_KEY`. Every `NEXT_PUBLIC_*` value is inlined into the client
  bundle at build time, so a key placed there is readable by anyone who loads the
  page - it would look like security while providing none.
* `lib/api-client.ts` attaches the key and classifies failures, because the
  remedies differ: 401 means "supply a key", 403 means the key lacks a scope and
  re-entering it cannot help. A thrown `fetch` (DNS, refused connection, CORS
  preflight) is reported as status 0 rather than as a server error, so a local
  connectivity problem does not blame the API.
* `/settings` reports the API's readiness and its active auth mode, which makes
  the commonest setup mistake - a mismatch between browser config and server auth
  mode - visible instead of leaving the user staring at a 401.
* Long-trip pagination: the list sends an explicit `limit`, since the API now
  rejects an unbounded one.

Tests (29):

* `lib/auth.test.ts` - storage round-trip, whitespace trimming, the change event,
  and graceful degradation when `localStorage` throws (private browsing).
* `lib/api-client.test.ts` - bearer attachment, param building (including the
  `offset=0` falsy trap), and each error class. The negative cases assert the
  request actually rejected, so an unexpected success cannot pass silently.

Fixes found while wiring this up:

* `readDetail` returned a non-JSON error body verbatim, which would render an
  upstream proxy's HTML error page into the UI. Short plain-text bodies are still
  used; markup falls back to a generic message.
* Untracked `apps/web/tsconfig.tsbuildinfo`, a build artefact that changed on
  every build.

CI gains an `npm test` step and a post-build guard that fails if
`NEXT_PUBLIC_API_KEY` or a literal `trv_` key appears in `.next/static`, so the
no-secret-in-the-bundle claim is enforced rather than merely documented.

Verified: 291 python tests passed (8 skipped), ruff check and format clean,
web tsc/lint/test/build clean, no secret in any of the 19 built bundles.
